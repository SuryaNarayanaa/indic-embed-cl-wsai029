Abstract
This report presents the work carried out during the WSAI Summer Internship on multilingual Indic sentence embeddings. The objective of the project was to evaluate and improve cross-lingual alignment for Indian languages, with a focus on Indic-Indic sentence representation using contrastive-learning-based methods. The work began with a literature survey of Indic NLP resources, Sentence-BERT, Contriever/mContriever, SimCSE, and LaBSE. It then moved into the design of benchmarking pipelines using FLORES-200, Samanantar, and IN22-Gen/IN22-Conv. Several embedding models were compared using retrieval metrics, alignment metrics, and separation metrics. The experiments showed that LaBSE is a strong baseline for cross-lingual alignment, but that average cosine similarity alone can be misleading when wrong pairs also receive high similarity. Therefore, cosine gap, Accuracy@1, Recall@10, MRR, sensitivity, and specificity were used together for a more reliable evaluation. The final stage explored LaBSE fine-tuning on top-performing and bottom-performing Indic language pairs. Single-pair fine-tuning improved cosine-gap performance over the baseline, while combined bottom-pair training showed signs of conflicting training signals. The report concludes that LaBSE remains the most reliable overall model for Indic alignment, Vyakyarth is a strong competitor in cosine-gap separation, and targeted contrastive fine-tuning is a promising direction for low-resource Indic languages.

1. Introduction
India has a large linguistic landscape with many scheduled languages, multiple scripts, and unequal availability of digital resources. In multilingual NLP, a sentence embedding model should map semantically equivalent sentences from different languages to nearby vectors in a shared representation space. Such embeddings are useful for cross-lingual retrieval, translation mining, semantic search, alignment analysis, clustering, and downstream multilingual applications.
The project, "Multilingual Indic Text Embedding Model using Contrastive Learning", investigated how well existing multilingual and Indic-focused embedding models align Indic languages. The work progressed from small pilot benchmarks to all-pair multilingual evaluation, then to IN22 evaluation across all 22 scheduled Indic languages, and finally to LaBSE fine-tuning on selected strong and weak language pairs.
A central lesson from the project is that high cosine similarity between gold translation pairs is not sufficient by itself. A model can assign high similarity to correct pairs and also assign high similarity to wrong pairs. For a useful embedding space, correct pairs must be close while incorrect pairs must be clearly farther away. This separation was captured using cosine gap, retrieval metrics, and later sensitivity/specificity analysis.
2. Problem Statement and Objectives
2.1 Problem Statement
The problem is to evaluate and improve sentence embedding alignment for Indic languages. Given two sentences in different languages that express the same meaning, the embedding model should place them close together. Given unrelated or randomly mismatched sentences, the model should place them farther apart. The project specifically focused on multilingual Indic text embedding using contrastive learning and evaluated whether existing models can support reliable cross-lingual and Indic-Indic alignment.
2.2 Objectives
Study the literature on Indic NLP resources, multilingual sentence embeddings, and contrastive learning.
Build a benchmark pipeline for evaluating multilingual sentence embedding alignment.
Compare multiple embedding/backbone models on FLORES-200, Samanantar, and IN22 benchmarks.
Evaluate both English-Indic and Indic-Indic language directions.
Compare threshold cosine, average cosine, retrieval metrics, cosine gap, sensitivity, and specificity.
Identify strong and weak language-pair directions, especially for low-resource Indic languages.
Fine-tune LaBSE using selected top-performing and bottom-performing language pairs and evaluate generalisation.
2.3 Scope
The work is sentence-level rather than document-level. The primary task is alignment and retrieval of parallel sentences. The project does not train a new embedding model from scratch; it evaluates pretrained models and fine-tunes LaBSE variants using contrastive objectives. The final benchmarks focus on IN22-Gen and IN22-Conv because they cover all 22 scheduled Indic languages plus English.

4. Datasets Used
4.1 FLORES-200
FLORES-200 was used for the initial cross-lingual benchmark and for a clean Indic-Indic evaluation. The dev and devtest splits were combined, giving 2,009 aligned examples per language in the pilot benchmark. Because FLORES is multi-way aligned, row i in one language corresponds to the same underlying meaning as row i in another language. This makes it suitable for retrieval-style evaluation.
4.2 Samanantar and Samanantar-EnglishPivot
Samanantar was used in two ways. First, it was used for English-Indic retrieval and gold-pair cosine evaluation. Second, because direct Indic-Indic parallel files were not available in the used setup, Indic-Indic pairs were constructed through an English pivot. English(A)-Indic1(B) and English(A)-Indic2(C) pairs were joined using normalized English text to form inferred Indic1(B)-Indic2(C) pairs. This created a useful but noisier benchmark because the Indic-Indic pair is inferred rather than directly verified.
4.3 IN22-Gen and IN22-Conv
The final benchmark moved to IN22 because it covers all 22 scheduled Indic languages plus English. IN22-Gen contains general-domain sentences such as news, Wikipedia-style, culture, and general information. IN22-Conv contains conversational and daily-use sentences, making it a harder and more informal test setting. The evaluation used two tracks: 462 Indic-Indic directed pairs and 44 English-Indic bidirectional pairs.

6. Evaluation Methodology
6.1 Embedding and Similarity Pipeline
Load aligned sentences from the chosen dataset.
Encode source and target language sentences into vector embeddings.
Normalize embeddings so that dot product is equivalent to cosine similarity.
Construct an n x n similarity matrix for each directed language pair.
Treat the diagonal entries as gold translation-pair similarities.
Use off-diagonal or shuffled entries as random/wrong-pair similarities.
Compute retrieval, alignment, separation, and threshold-based metrics.
Save summary CSVs, pair-level CSVs, plots, heatmaps, and error examples.
6.2 Metrics
[TABLE]
Metric | Meaning | Interpretation
Accuracy@1 | Fraction of cases where the correct translation is ranked first. | Primary retrieval signal. Higher is better.
Recall@10 | Fraction of cases where the correct translation is within top 10 candidates. | Measures whether the gold pair is near the top even if not rank 1.
MRR | Mean reciprocal rank of the correct translation. | Rewards gold translations appearing near the top.
Mean gold cosine | Average cosine similarity of true translation pairs. | Alignment score, but insufficient alone.
Mean random cosine | Average similarity of random/wrong sentence pairs. | High values indicate score inflation or poor uniformity.
Cosine gap | mean_gold_cosine - mean_random_cosine. | Primary separation/discrimination signal.
Sensitivity | Fraction of true pairs above threshold. | True positive rate.
Specificity | Fraction of random pairs below threshold. | True negative rate.
[/TABLE]
6.3 Threshold Design for Sensitivity and Specificity
Based on professor feedback, sensitivity and specificity were added to the IN22 evaluation. For each directed language pair, a single threshold t is used for both gold and random pairs. Sensitivity measures how many gold pairs score above t, while specificity measures how many random pairs score below t. Two thresholding schemes were used: midpoint threshold and optimal threshold.
Midpoint threshold: t = (mean_gold_cosine + mean_random_cosine) / 2 for each language pair.
Optimal threshold: selected by grid search to maximize F1 for that language pair.
Thresholds are computed independently per directed pair; the average threshold is only a summary and is not used as one global cutoff.

8. Fine-tuning Experiments
8.1 Motivation
After identifying strong and weak language directions, LaBSE fine-tuning was explored to check whether contrastive training on selected pairs can improve alignment. The training experiments focused on top-5 and bottom-5 language pairs from IN22 alignment results. The core idea was to compare whether training on already strong directions, weak directions, or mixed directions leads to better generalisation on unseen IN22-Conv.

8.5 Interpretation of Fine-tuning Results
All 10 single-pair models improved cosine gap over the LaBSE baseline.
The best model was bottom_single_5_ben_to_mni with cosine gap 0.4624, an improvement of +0.0954 over baseline 0.3670.
Bottom-pair models performed surprisingly well, suggesting that training on difficult low-resource/script-specific directions can improve separation across the full set of 462 pairs.
top5_all_directed_pairs improved over baseline but less than most single-pair models.
bottom5_all_directed_pairs performed worst, suggesting that combining multiple difficult low-resource directions with limited examples may introduce conflicting gradients and reduce general alignment.
mixed_top5_bottom5 achieved high sensitivity but lower specificity and lower Accuracy@1, meaning it became too inclusive and allowed more false positives.
9. Discussion
9.1 Alignment vs Uniformity
The project repeatedly showed that alignment and uniformity must be evaluated together. Alignment means true translation pairs are close. Uniformity means the vector space is spread out so that wrong candidates are not also close. Average gold-pair cosine mainly checks alignment, while retrieval metrics and cosine gap check whether correct pairs can be separated from wrong pairs.
9.2 Why Mean Cosine Alone Can Mislead
XLM-RoBERTa and MuRIL under mean pooling showed very high mean gold-pair cosine in some benchmarks, but their random-pair cosine was also very high. This means the embedding space had score inflation or anisotropy: many sentences became close to many other sentences. Such a model can look strong under average cosine but fail under retrieval because the correct translation is not distinctly separated.
9.3 Language Resource and Script Effects
The IN22 analysis showed strong variation across languages. Many high-resource languages had strong cosine gaps, while Manipuri/Meitei and Santali were critical weak points. Their low mean gold cosine and small gap suggest that the model does not align these languages well with the rest of the Indic space. This may be connected to limited representation in multilingual training data and script-specific challenges such as Meitei Mayek and Ol Chiki.
9.4 General-domain vs Conversational-domain Evaluation
IN22-Conv was consistently harder than IN22-Gen. Conversational sentences are shorter, more informal, and more dependent on context. This reduced Accuracy@1 and cosine gap, but also made IN22-Conv a valuable evaluation set for testing whether fine-tuned models generalise beyond formal/general-domain text.
10. Implementation Details
Implemented evaluation notebooks in Google Colab / Python using sentence-transformers, Hugging Face Transformers, PyTorch, NumPy, pandas, scikit-learn, tqdm, and plotting libraries.
Used embedding caches per model-language-split-size combination to avoid recomputation.
Generated similarity matrices for every source-target pair and computed diagonal gold-pair scores and random-pair scores.
Saved metrics CSVs, model summaries, language-pair summaries, best/worst pair tables, error files, heatmaps, and report documents.
Implemented all-pair directed evaluation, English-Indic bidirectional evaluation, Indic-Indic evaluation, midpoint/optimal threshold sensitivity-specificity evaluation, and fine-tuning/evaluation notebooks.
Used MultipleNegativesRankingLoss during LaBSE fine-tuning, where other examples in the batch act as implicit negatives.

11. Limitations
The evaluation is sentence-level and does not directly test document retrieval or long-context semantic search.
Some backbone models were evaluated with simple mean pooling, so their results should not be treated as their best possible performance.
Samanantar-EnglishPivot Indic-Indic evaluation is noisy because pairs are inferred through English rather than directly verified.
Fine-tuning used limited examples and short training runs, so more extensive hyperparameter tuning may change conclusions.
Sensitivity/specificity thresholds were computed per language pair, so care is needed when comparing aggregated thresholds.
The paper-reading notes linked through Notion were not directly accessible inside this environment; the literature-review section uses the paper summaries provided in the chat and project notes.
12. Future Work
Run larger and more systematic fine-tuning experiments with controlled hyperparameter sweeps.
Test hard-negative mining instead of relying only on in-batch negatives.
Evaluate whether low-resource languages such as Manipuri/Meitei and Santali improve with script-aware preprocessing or transliteration support.
Compare LaBSE, Vyakyarth, MPNet, and fine-tuned LaBSE variants on external retrieval datasets such as MIRACL or Indic-specific retrieval benchmarks.
Add qualitative error analysis for weak language pairs by inspecting source sentence, gold translation, predicted nearest neighbour, and similarity margins.
Study whether combining top and bottom pairs with balanced sampling or curriculum learning avoids the degradation observed in bottom5_all_directed_pairs.
Create a reusable benchmark package with configuration files, cached embeddings, metric scripts, and automatic report generation.
13. Conclusion
The internship work built a progressively stronger evaluation pipeline for multilingual Indic sentence embeddings. Starting from a FLORES-200 retrieval benchmark, the project expanded to Samanantar, English-pivot Indic-Indic evaluation, and finally IN22 evaluation covering all 22 scheduled Indic languages. The project showed that LaBSE is the strongest overall baseline for Indic alignment when both retrieval and separation are considered. Vyakyarth is a strong alignment competitor because of its high cosine gap, but LaBSE remains more reliable in Accuracy@1, Recall@10, and MRR.
The most important methodological conclusion is that average cosine similarity alone is insufficient. A useful embedding model must keep true translation pairs close and random/wrong pairs far apart. Therefore, cosine gap, retrieval metrics, sensitivity, specificity, and error analysis should be reported together. The fine-tuning experiments showed that targeted single-pair contrastive fine-tuning can improve LaBSE over the baseline, especially when training on weak pair directions. However, combined bottom-pair training can degrade performance, indicating that low-resource directions require careful sampling and training design.
Overall, the project establishes a clear baseline and evaluation framework for future work on multilingual Indic text embeddings using contrastive learning. It also identifies the main research gap: improving robust Indic-Indic alignment for low-resource and script-specific languages without reducing general cross-lingual performance.

C.2 SBERT: Sentence Embeddings from BERT-style Encoders
The SBERT notes explain why standard BERT/RoBERTa cross-encoders are accurate but inefficient for large-scale similarity search. In a cross-encoder, both sentences are fed together, so every candidate pair must be recomputed. For a collection of 10,000 sentences, this leads to nearly 50 million pairwise comparisons, which is impractical for retrieval-style evaluation.
SBERT changes this by using a bi-encoder design: each sentence is independently encoded into a reusable vector, and sentence similarity is computed using cosine similarity. This directly motivated the project evaluation pipeline, where each language split is encoded once and then compared using a full cosine-similarity matrix.
Key method: Siamese/triplet network fine-tuning converts BERT/RoBERTa into a sentence-embedding model.
Pooling studied: CLS pooling, mean pooling, and max pooling; the notes highlight mean pooling as a strong default in SBERT-style sentence embeddings.
Training objectives: classification over NLI labels, regression for STS similarity scores, and triplet loss for anchor-positive-negative training.
Project relevance: SBERT established the difference between token-level language models and sentence-level embedding models, which became important when interpreting why raw XLM-R and IndicBERT-style backbones performed poorly under simple mean pooling.
C.3 SimCSE: Contrastive Learning, Alignment, and Uniformity
The SimCSE notes were important for understanding contrastive learning as an embedding-space objective. Unsupervised SimCSE treats the same sentence passed twice through dropout as a positive pair, while other batch examples become negatives. Supervised SimCSE uses NLI entailment pairs as positives and contradiction pairs as hard negatives.
The main conceptual contribution for this project was the distinction between alignment and uniformity. Alignment means semantically equivalent sentences should be close; uniformity means the embedding space should not collapse so that unrelated sentences also become close. This concept later became central to explaining why high average cosine can still be misleading if random pairs also have high cosine similarity.
Unsupervised positive creation: same sentence, different dropout masks.
Supervised positive/negative creation: entailment pairs as positives and contradiction pairs as hard negatives.
Embedding-space issue: anisotropy causes many sentence vectors to occupy a narrow region, making unrelated sentences look artificially similar.
Project relevance: motivated reporting cosine gap, sensitivity, specificity, and retrieval metrics rather than only reporting mean gold-pair cosine.
C.4 Contriever and mContriever: Dense Retrieval without Labeled Pairs
The Contriever/mContriever notes helped connect contrastive learning to retrieval. The paper studies whether a dense retriever can be trained from raw unaligned documents instead of labeled query-document pairs. It uses a bi-encoder architecture where query and document spans are encoded independently and compared by dot product.
The notes emphasize positive-pair construction through independent random cropping: two spans from the same document are treated as related views, while spans from other documents act as negatives. The model is optimized with InfoNCE-style contrastive loss. mContriever extends this idea to multilingual retrieval and shows why contrastive methods are useful in low-resource settings where labeled retrieval data is limited.
Key training idea: construct positives automatically from raw documents using cropping or related context.
Negative strategy: use in-batch negatives and MoCo-style queues/momentum encoders to increase the number of stable negatives.
Project relevance: informed the use of in-batch negatives and retrieval-style evaluation for multilingual embedding models.
C.5 LaBSE: Translation Ranking for Cross-lingual Sentence Alignment
The LaBSE notes were the most directly connected to the project because LaBSE is a language-agnostic sentence embedding model trained for bitext retrieval. LaBSE uses a shared dual encoder to map source and target sentences into one vector space, where translation pairs should have high similarity and non-translations should have low similarity.
The paper combines multilingual pretraining with dual-encoder translation ranking and additive margin softmax. In each batch, the correct translation is the positive target and the other target sentences are in-batch negatives. The bidirectional loss trains both source-to-target and target-to-source retrieval. Additive margin softmax forces the correct pair to be clearly better than wrong pairs, not just slightly better.
Training components studied: MLM, TLM, translation ranking loss, bidirectional loss, in-batch negatives, and additive margin softmax.
Representation: the notes describe extracting sentence embeddings from the final CLS representation with L2 normalization in the LaBSE setup.
Project relevance: LaBSE became the primary baseline because its training objective directly matches cross-lingual translation retrieval and sentence alignment.
Limitation noted: LaBSE is stronger for translation-equivalence retrieval than for fine-grained partial semantic similarity, which is why evaluation should match the task objective.
C.6 AI4Bharat IndicNLP Corpus, IndicBERT v2, and IndicXTREME
The IndicNLP and IndicBERT v2 notes explain the data and benchmark background behind Indic-specific language models. The 2020 IndicNLP Corpus work built a large news-crawled corpus for Indic languages and trained FastText embeddings, showing the importance of high-quality Indic data. The later IndicBERT v2 work expanded this into IndicCorp v2, IndicBERT v2, and IndicXTREME.
IndicCorp v2 is described in the notes as a large 24-language corpus covering the 22 scheduled Indian languages, Indian English, and related languages. IndicBERT v2 uses MLM and TLM objectives; TLM is especially relevant because it uses parallel text to encourage cross-lingual alignment. IndicXTREME provides evaluation tasks including sentence retrieval, which aligns closely with this internship project.
Main project insight: Indic languages require dedicated evaluation because global multilingual models and tokenizers often favor high-resource languages.
Dataset insight: FLORES, Samanantar, IndicXParaphrase, and IndicXTREME are relevant because they provide sentence-level or retrieval-style evaluation signals.
Data-quality insight: high-quality parallel data helps cross-lingual alignment, while noisy back-translated or weakly aligned data can hurt contrastive training.
Model-selection insight: IndicBERT v2, IndicBERT-SS, and MuRIL are important Indic-focused baselines, but they still need sentence-embedding adaptation for retrieval-style use.
C.7 Vyakyarth: Indic Semantic Embedding Model
The Vyakyarth notes describe it as a multilingual Indic sentence embedding model focused on semantic retrieval and cross-lingual alignment. Unlike general multilingual language models that mainly learn token-level language understanding, Vyakyarth is positioned as a sentence embedding model that maps semantically equivalent Indian-language sentences into a shared vector space.
The notes emphasize that Vyakyarth is based on XLM-R and is fine-tuned for Indic semantic embeddings using contrastive-learning-style objectives. It is relevant for semantic search, multilingual retrieval, clustering, recommendations, and retrieval-augmented generation. This made Vyakyarth an important comparison model in the later IN22 evaluation, where it achieved a strong cosine gap but lower retrieval scores than LaBSE.
Core goal: same meaning across languages should produce nearby embeddings.
Technical focus: contrastive learning, semantic alignment, cosine similarity, and cross-lingual embedding geometry.
Project relevance: used as a strong Indic semantic embedding competitor to LaBSE, especially for alignment and cosine-gap analysis.
C.8 How the Notion Readings Shaped the Final Methodology
The Notion paper notes did not remain separate from the implementation; they directly shaped the project methodology. SBERT motivated the use of reusable sentence embeddings and cosine matrices. SimCSE motivated the use of alignment/uniformity language and contrastive separation. Contriever motivated retrieval-style evaluation and negative sampling. LaBSE motivated translation retrieval and additive-margin-style separation. IndicBERT/IndicXTREME motivated all-Indic language coverage and careful dataset choice. Vyakyarth motivated comparison against a newer Indic-specific semantic embedding model.
Evaluation design moved from only mean cosine to a combined framework: Accuracy@1, Recall@10, MRR, mean gold cosine, random cosine, cosine gap, sensitivity, specificity, and qualitative error analysis.
Dataset design moved from six-language FLORES testing to all-22-language IN22-Gen and IN22-Conv evaluation.
Model design moved from benchmarking ready-made embeddings to testing whether targeted contrastive fine-tuning on top/bottom language pairs improves LaBSE.
Interpretation changed from asking only whether true pairs are close to asking whether true pairs are close and wrong pairs are far enough for reliable retrieval.
